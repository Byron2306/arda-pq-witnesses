# ARDA post-quantum quorum: original v1 design

Historical design. Version 2 adds pinned raw R13 verification and a separate candidate reservation ledger. Current boundaries are in `R13_AND_RELEASE_LEDGER.md`.

Build the agreed three-witness software quorum in an isolated package. GitHub uses ML-DSA-65; Hugging Face uses SLH-DSA-SHA2-192s; the Cloudflare release witness uses one-level HSS/LMS SHA256 N32 H10 W8. The LMS public verifier is stateless; the live stateful signer is not implemented or enrolled by this package. Every witness is mandatory. There is no algorithm negotiation or classical fallback.

A protected operator enrollment policy pins identity, provider, role, algorithm, public key bytes, policy epoch and validity. Votes sign a domain-separated canonical payload binding the same exact proposal digest, enrollment policy digest, witness identity, key digest, decision and time interval. Proposals bind machine, boot, generation, manifest, deployment, artifact root, intended action, nonce, evidence digest and expiry. Only review of a staged release is in scope; no installation/execution action is exposed.

Use OpenSSL 3.5+ for ML-DSA and SLH-DSA. Use unmodified, blob-hash-verified Cisco hash-sigs source for HSS/LMS verification and disposable test fixtures. Do not implement signature primitives from scratch. Pin concrete key encodings and parameter sets; missing backends refuse.

Replay consumption uses FULL-synchronous SQLite transactions and a unique nonce plus HSS leaf identity. A crash after consumption cannot grant a second attempt. This journal records review intent, never an execution or production-admission receipt. The database must be private to the verifier. Its integrity does not establish rollback-resistant external storage.

Create a minimal public commitment containing the certificate digest, suitable for a supported outer Sigstore/Rekor format. Do not upload the full host request. This version does not mint Rekor evidence, accept a Rekor PASS boolean, publish to the log, verify a live R13 quote or enroll cloud services. Those missing integrations keep release admission closed even when all three PQ signatures verify.

The sealed generation-14 request is an input for preparing a review proposal. No generation-14 files, signatures, selectors, systemd units, BPF objects, TPM state or cloud resources are changed. Adding this verifier to the measured runtime will require a later sealed proposal. No production signing keys are generated by the test runner.

Validation: real signatures from all three implementations; source-provided HSS test vectors; tamper/algorithm/identity/role/epoch/time/binding failures; durable replay, leaf reuse and concurrent consumption; no missing-signature downgrade; actual generation-14 proposal binding; explicit closed admission with absent R13/Rekor integrations.
