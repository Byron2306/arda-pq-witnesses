# Controlled Cloudflare orphaned-key replacement

Byron delegated the choice on 2026-11-16. Choose provider-local replacement over reusing leaf zero or extending registration to a later leaf. Preserve the original key (257b983a…6b3f933), counter and immutable burn marker. Production remains unauthorized.

Add an authenticated, explicit POST /v1/replace-orphaned-key. Require canonical, bounded input binding the current configuration/ceremony, original public ceremony, expected old fingerprint, exact counter 1 and expected immutable leaf-zero tag object SHA. Verify the original ceremony hash against stored state and the complete original registration message against a fresh protected GitHub marker read. Refuse cached registration, quarantined state, changed counter/key, invalid pin, or expired current configuration.

Generate a replacement entirely inside the same Durable Object. Before exposing its fingerprint, atomically write the old private state to an immutable retired/<old SHA> record with state RETIRED, replace only the primary key with the newly generated q=0 state, and cache a public replacement receipt under a digest of the exact request. The old serialized counter is never modified. Check durability before returning. Replaying the exact completed request returns its existing receipt, including after the replacement has enrolled; it never generates another key. Refuse an existing retirement archive without a matching completed receipt. Keep the namespace, class, object name and Wasm unchanged.

The replacement endpoint does not sign or burn any new leaf. A separate enrollment request uses the reviewed atomic key/public-registration write. No path reads archived keys for signing or exports their private state. Existing completed registrations cannot be rotated by this endpoint.

Add a host-side standard-library operator client using curl IPv4/HTTP2, no proxy, redirect, retry or shell execution. Token travels through stdin, not argv. Reserve public response files before requests and retain responses even on HTTP/native-verification failure. Validate configuration and request pins before mutation; retain original ceremony timestamps. Verify a returned registration offline with the accepted v5 Docker image, then export only its canonical public envelope. Read-only status remains usable after expiry. If the current ceremony expires, refuse mutation: prepare a genuinely new ceremony and refresh provider proofs while preserving existing provider private keys; never extend old timestamps.

Alternatives: next-leaf re-registration retains the key but changes the accepted enrollment recovery rules; resetting or removing markers is rejected. Namespace replacement hides rather than retires the old state and is rejected. This design changes the witness fingerprint deliberately and retains a public audit link.

Review resolution: exact POST replay remains subject to the live mutation window. After expiry, authenticated read-only status returns the same complete public receipt bound to the installed replacement key and request digest. No expired mutation path is opened. Curl starts with --disable, removes inherited proxy/TLS-key-log overrides, and reports success only after HTTP/2 was negotiated; a non-H2 public response is retained for diagnosis. Native readiness executes the pinned verifier binary before enrollment, and proof verification runs offline after the public response has been saved.
