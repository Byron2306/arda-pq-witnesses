# Existing-key registration renewal

Byron delegated the implementation choices and requested continuation after successful Cloudflare enrollment. Renew GitHub/HF proofs for the replacement ceremony without replacing either provider-held private key. Cloudflare is complete and must not be enrolled again.

Use one small Python overlay on the already accepted immutable v4 image. The overlay selects the exact fingerprint-named secret, validates provider identity, canonical ceremony pin, image digest, time window, and derived public-key fingerprint before signing the existing registration domain. It cannot generate keys or write provider secrets. GH runs offline after the image is pulled, within the existing protected enrollment environment, with exact approved workflow ref/commit. HF exposes a distinct authenticated renewal endpoint; it signs only on POST, caches its public response, never serves votes, and expires with the ceremony. Existing provisioning paths remain distinct and disabled.

Alternatives: rerun provisioning (rejected: generates new keys); export private keys to Debian (rejected: breaks custody); provider-local renewal (selected by implementer under delegated authority). Wrapper source is a separately pinned overlay, not a claim that the wrapper itself has the original digest. All outputs remain production_authorized=false / KEEP_CLOSED.
